# MAVLink C Library #defines

The C library generated by _mavgen_ can be configured for different platforms and uses by defining the macros below.
They must be defined before the library headers (e.g. `mavlink.h`) are included, usually in a single header that your code includes instead of the MAVLink headers.

Each entry links to where the library tests the macro, and to where [PX4](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_bridge_header.h) and [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h) set it (if they do).

## Sending

### MAVLINK_USE_CONVENIENCE_FUNCTIONS {#mavlink_use_convenience_functions}

Enables the `mavlink_msg_*_send()` functions in the generated message headers, and the helpers they use (`_mav_finalize_message_chan_send()`, `_mavlink_send_uart()`, `_mavlink_resend_uart()`).
If defined you must also declare a global `mavlink_system_t mavlink_system` (the sending system and component IDs), and define either `MAVLINK_SEND_UART_BYTES` or `comm_send_ch()`.
Leave it undefined if you pack and write out messages with your own code (see [Transmitting](../mavgen_c/index.md#transmitting)).

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L405).
Set by: [PX4](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_bridge_header.h#L47), [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h#L78).

### MAVLINK_SEND_UART_BYTES {#mavlink_send_uart_bytes}

`MAVLINK_SEND_UART_BYTES(chan, buf, len)` writes `len` bytes to the channel.
If not defined, the library instead calls `comm_send_ch(chan, ch)` for each byte, which you must then provide.

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L1262).
Set by: [PX4](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_bridge_header.h#L50), [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h#L13).

### MAVLINK_START_UART_SEND, MAVLINK_END_UART_SEND {#mavlink_start_uart_send}

`MAVLINK_START_UART_SEND(chan, length)` and `MAVLINK_END_UART_SEND(chan, length)` are called before and after each packet is written by the convenience functions (empty by default).
For example, ArduPilot uses them to lock the channel while a packet is written.

Source: [protocol.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/protocol.h#L28).
Set by: [PX4](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_bridge_header.h#L52-L53), [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h#L15-L16).

## Channels

### MAVLINK_COMM_NUM_BUFFERS {#mavlink_comm_num_buffers}

Maximum number of [channels](../mavgen_c/index.md#channels), and hence of the receive buffers and status structures allocated by the library (one of each per channel).
By default this is 16 on Linux, Windows and macOS, and 4 on other platforms.
You might reduce this to save memory (e.g. to `1` on a system with only one link).
Using a channel number at or above this value will overrun the arrays.
See also [FAQ > How can I further reduce the generated C library size?](../about/faq.md#how-can-i-further-reduce-the-generated-c-library-size).

Source: [mavlink_types.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_types.h#L190).
Set by: [PX4](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_bridge_header.h#L59), [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h#L18-L28).

### HAVE_MAVLINK_CHANNEL_T {#have_mavlink_channel_t}

The default `mavlink_channel_t` enum only defines `MAVLINK_COMM_0` to `MAVLINK_COMM_3`.
Define this and declare your own `mavlink_channel_t` if you use more channels.

Source: [mavlink_types.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_types.h#L176).
Set by: [PX4](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_bridge_header.h#L62-L71).

### MAVLINK_GET_CHANNEL_STATUS, MAVLINK_GET_CHANNEL_BUFFER {#mavlink_get_channel_status}

Define to provide your own `mavlink_get_channel_status(uint8_t chan)` and `mavlink_get_channel_buffer(uint8_t chan)`, instead of the library versions that return entries from `static` arrays.
This allows you to keep the per-channel state wherever you like (the value of the macro is not used).

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L26-L56).
Set by: [PX4](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_bridge_header.h#L55-L56) ([implementation](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_main.cpp#L156-L157)), [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h#L32-L33) ([implementation](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.cpp#L44-L66)).

### MAVLINK_EXTERNAL_RX_STATUS, MAVLINK_EXTERNAL_RX_BUFFER {#mavlink_external_rx_status}

Keep the library versions of the functions above, but have them use arrays that you define, named `m_mavlink_status` (of `mavlink_status_t`) and `m_mavlink_buffer` (of `mavlink_message_t`), instead of `static` arrays inside the functions.
These must be visible where `mavlink_helpers.h` is included (i.e. globals, or global pointers to memory that you allocate), with one entry per channel.

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L26-L56).

## Signing

Signing is enabled for each channel at runtime, as described in [C Message Signing](../mavgen_c/message_signing_c.md#enabling_signing_channel).
These macros configure the signing implementation.

### MAVLINK_MAX_SIGNING_STREAMS {#mavlink_max_signing_streams}

Maximum number of signing streams (`(link ID, system ID, component ID)` tuples) tracked to detect replayed packets.
Default 16.
Signed packets from new streams are rejected once this limit is reached.

Source: [mavlink_types.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_types.h#L292).

### MAVLINK_SIGNING_TIMESTAMP_LIMIT {#mavlink_signing_timestamp_limit}

A signed packet from a new stream is rejected if its timestamp is more than this many seconds older than the local signing timestamp.
Default 60.

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L15).

### MAVLINK_NO_SIGN_PACKET {#mavlink_no_sign_packet}

Removes the code for signing outgoing packets (packets are never signed).

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L73).

### MAVLINK_NO_SIGNATURE_CHECK {#mavlink_no_signature_check}

Removes the code for checking the signatures of incoming packets (signed packets are accepted without being verified).

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L185).

## Parsing

### MAVLINK_CHECK_MESSAGE_LENGTH {#mavlink_check_message_length}

Rejects incoming messages with a payload length outside the minimum and maximum for their message ID.
See [Additional Checks](../mavgen_c/index.md#additional-checks).

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L860).

### MAVLINK_GET_MSG_ENTRY {#mavlink_get_msg_entry}

Define to provide your own `mavlink_get_msg_entry(uint32_t msgid)`, which returns the CRC extra, lengths, and target field offsets for a message ID.
The library version does a bisection search of the dialect's `MAVLINK_MESSAGE_CRCS` table.

Source: [mavlink_helpers.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_helpers.h#L581).

## Code Size

### MAVLINK_MAX_PAYLOAD_LEN {#mavlink_max_payload_len}

Maximum payload length (default 255 bytes).
Reducing it reduces the size of `mavlink_message_t`, and hence of every channel buffer.
It cannot be increased, because the payload length is stored in a `uint8_t`.
Incoming packets with a longer payload are rejected, and the `mavlink_msg_*_send_buf()` functions are not generated for messages that are longer.
For example, to reduce the maximum payload to the largest message in your dialect:

```c
#include <mavlink/common/version.h>
#define MAVLINK_MAX_PAYLOAD_LEN MAVLINK_MAX_DIALECT_PAYLOAD_SIZE
#include <mavlink/common/mavlink.h>
```

See also [FAQ > How can I further reduce the generated C library size?](../about/faq.md#how-can-i-further-reduce-the-generated-c-library-size).

Source: [mavlink_types.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_types.h#L22).
Set by: [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h#L46-L48) (to 255).

### MAVLINK_SEPARATE_HELPERS {#mavlink_separate_helpers}

Declares the helper functions in `mavlink_helpers.h` as ordinary functions, instead of defining them as `static inline` in every file that includes the library.
You must then compile them once, normally by including `mavlink_helpers.h` in a single source file, or provide your own implementation.

Source: [protocol.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/protocol.h#L157).
Set by: [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h#L10) ([compiled in](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.cpp#L35-L42)).

### MAVLINK_NO_CONVERSION_HELPERS {#mavlink_no_conversion_helpers}

Omits the quaternion, Euler angle, and rotation matrix conversion functions (`mavlink_quaternion_to_euler()` and so on).

Source: [mavlink_conversions.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_conversions.h#L3).
Set by: [PX4](https://github.com/PX4/PX4-Autopilot/blob/f364b94f088165ebdc324e7edfae14767beb5bad/src/modules/mavlink/mavlink_bridge_header.h#L45), [ArduPilot](https://github.com/ArduPilot/ardupilot/blob/6034266b5abffd36fb4b89f0bf61fb6db8aed85d/libraries/GCS_MAVLink/GCS_MAVLink.h#L11).

### MAVLINK_USE_MESSAGE_INFO {#mavlink_use_message_info}

Adds `mavlink_get_message_info()`, `mavlink_get_message_info_by_id()` and `mavlink_get_message_info_by_name()`, which return the name, type and offset of each field in a message.
This is off by default because it adds a table describing every message in the dialect.

Source: [mavlink_get_info.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/mavlink_get_info.h#L3).

## Platform

### NATIVE_BIG_ENDIAN {#native_big_endian}

Define if using MAVLink on a system that is natively big-endian, so that fields are byte-swapped to and from the little-endian wire format.

Source: [protocol.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/protocol.h#L10).

## WIP/Deprecated/Superseded Diagnostics

`MAVLINK_WIP`, `MAVLINK_DEPRECATED`, `MAVLINK_SUPERSEDED`, `MAVLINK_ENUM_WIP`, `MAVLINK_ENUM_DEPRECATED`, `MAVLINK_ENUM_SUPERSEDED`, and (C++ 11 only) `MAVLINK_MSG_TYPE_WIP`, `MAVLINK_MSG_TYPE_DEPRECATED`, `MAVLINK_MSG_TYPE_SUPERSEDED` are empty by default.
Define them as compiler attributes, such as `__attribute__((deprecated("...")))`, to get compile-time diagnostics where your code uses WIP, deprecated, or superseded messages and enum entries.

## Testing

### MAVLINK_ASSERT {#mavlink_assert}

`MAVLINK_ASSERT(x)` is the assertion used by the generated test suites (`testsuite.h`).
Empty by default.

Source: [protocol.h](https://github.com/ArduPilot/pymavlink/blob/4fd5b57831b047ea6f77469994be7d898505870e/generator/C/include_v2.0/protocol.h#L24).

## Other Macros

Other macros in the headers, such as `MAVLINK_NEED_BYTE_SWAP`, `MAVLINK_ALIGNED_FIELDS`, `MAVLINK_CRC_EXTRA` and `MAVLINK_USE_CXX_NAMESPACE`, are set by the library or generated headers and should not be modified.
